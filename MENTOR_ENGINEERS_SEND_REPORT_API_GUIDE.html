External WhatsApp Send-Report API Specification & Integration Guide
Environment: Production Gateway
Standard: RESTful JSON / GET API
Active & Verified • v2.0 (Audited)

1. Overview & System Architecture

The send-report-mentor-engineeros API provides external billing software, Point-of-Sale (POS) terminals, enterprise ERPs, and diagnostic scanners with a direct, authenticated gateway to dispatch vehicle inspection reports, customer invoices, repair estimates, and service alerts via the official Mentor Engineers WhatsApp Business Account.

Core Capabilities & Features:
  • Real-time Dashboard Audit Trail: Every sent message and PDF is instantly archived into the workshop conversations database for customer service staff to review in real time.
  • Direct WhatsApp Delivery: High-performance instant delivery directly into customer WhatsApp chats without intermediary third-party delays.
  • Flexible Input Formats: Supports JSON payloads, multipart/URL-encoded form data, and standard GET query parameters.
  • Automatic Phone Normalization: Automatically handles Sri Lankan 10-digit mobile numbers (e.g. 074... is automatically converted to international standard 9474...).
  • Batch Dispatch: Supports sending to multiple phone numbers (up to 15 per request) in a single API invocation.

3. Request Parameters Reference

Field Name Type Required? Description & Validation Rules
number / numbers String / Array Required Recipient phone number (e.g. "94778428102" or "0778428102"). Comma-separated string or JSON array for bulk (max 15 numbers).
message String Optional* Text message body or document caption. Optional if document_url is supplied.
document_url String / Array Optional* Direct public URL of PDF, Image, or Document (Aliases: file_url, url, pdf_url). Must start with http:// or https://.
sessionId String Optional Custom session identifier for multi-account routing. Defaults to Mentor Engineers business profile.

*Note: Either message or document_url (or both) must be present in the request payload.

4. End-to-End Delivery Sequence

Step 1
Trigger API
Billing or ERP software sends POST request with recipient number and PDF report link.
Step 2
Authentication
API verifies the Bearer token and validates phone formatting & batch limits.
Step 3
WhatsApp Dispatch
Document and caption are delivered straight to customer WhatsApp chat.
Step 4
Audit Logging
Delivery record is saved into conversations table for workshop staff visibility.

7. API Response Specifications & Error Codes

Success Response (HTTP 200 OK):

{
  "success": true,
  "message": "Processed 1 numbers. Sent: 1, Failed: 0",
  "details": [
    { "number": "94740237915", "success": true }
  ]
}

Failure Response Example (HTTP 400 Bad Request):

{
  "success": false,
  "error": "Batch limit exceeded: Maximum 15 numbers allowed per request (received 18)."
}

HTTP Status Codes & Resolution Guide:

HTTP Code Error Type Root Cause & Resolution Guide
200 OK Success Request processed successfully. Check details array for per-recipient status.
401 Unauthorized Missing or invalid Authorization: Bearer ... header. Verify your API token.
400 Batch Limit Exceeded Maximum 15 numbers allowed per request. Split larger recipient batches into chunks of 15.
400 Invalid Document URL Document URL must be public and start with http:// or https://.
400 Missing Payload Both message and document_url are missing. Provide at least one valid field.

8. Data Storage Architecture & Privacy Policy

Storage Architecture & Document Privacy:

The send-report API streams the document directly from your public URL to WhatsApp. The binary document file is not stored on the server hard disk or database, preventing storage bloat and ensuring strict customer privacy. Only the delivery audit record (recipient phone, timestamp, caption, and URL reference) is securely logged in the workshop's private database for staff reference.

9. Developer Best Practices & Delivery Checklist

Integration Checklist:
  • Direct Public Links: Ensure document URLs point directly to the binary file (e.g. .pdf or .png) and are publicly reachable without requiring logins or CAPTCHAs.
  • Delivery Verification: Always inspect the returned details array in the response to confirm individual recipient delivery status.
  • Backoff & Retries: If sending multiple batches, add a 1-second delay between consecutive requests to ensure smooth delivery.
